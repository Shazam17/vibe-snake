# Дизайн: «Змейка» — нативное macOS-приложение

Дата: 2026-11-07
Статус: ждёт утверждения человеком (подход и объём уже выбраны).

## Задача (why)

Нативная игра «Змейка» для macOS: один Xcode-проект, только Apple SDK, без веб-обвязки и сторонних зависимостей. Цель — играбельный классический клон с сохранением рекорда; результат — запускаемое .app, которым удобно играть на Mac с клавиатуры.

## Цели (v1)

- Движение змейки по сетке стрелками / WASD, запрет разворота на 180°.
- Еда: съедена → рост на сегмент + счёт +1; новая еда появляется вне тела змейки.
- Столкновение со стеной или с собой → game over.
- Ускорение игры по мере роста счёта (с потолком).
- Пауза (пробел) и рестарт после смерти (ввод/пробел, кнопка в оверлее).
- Сохранение лучшего счёта между запусками; показ «нового рекорда» на экране game over.

## Не-цели / анти-цели (v1)

- Никаких сторонних пакетов (Swift Package Manager — только тесты Apple SDK), никаких веб-технологий, Electron/Flutter/WebAssembly.
- Без звуков, без уровней/препятствий, без геймпада и тачпад-управления, без мультиплеера/сетей.
- Анти-цель: «игра работает, но управление подтормаживает или окно не ловит клавиши» — считаем провалом даже при рабочей логике.

## Ограничения

- macOS deployment target 14.0 (SwiftUI Canvas — с 13.0; берём 14.0 для современного инструментария). Целевая машина: macOS 26.5, arm64, Swift 6.x → код компилируется в strict concurrency (Swift 6): игровой цикл и мутабельное состояние только на `@MainActor`.
- Одно оконное приложение; окно resizable в разумных пределах, игра адаптирует размер клетки под окно.

## Подходы (рассматривали три)

1. **SwiftUI + Canvas — выбрано.** Отрисовка сетки и сущностей одним `Canvas` по тикам игрового цикла; декларативное состояние через `@Observable`. Минимум кода, одна технологическая цепочка (Xcode target), хорошо тестируется: вся логика выносится из вью. Цена: игровой цикл нужно вести вручную (таймер/async-цикл) — для сетки 25×25 это тривиально.
2. **AppKit + NSView.** Императивный `draw(_:)`, полный ручной контроль кадра. Максимальная «классичность», но заметно больше кода и дублирование состояния между моделью и вью; для такого объёма игры — избыточно. Отклонено: не даёт выигрыша в рамках v1.
3. **SpriteKit.** Готовый игровой цикл, анимации узлов, физика — всё под iOS-ориентированные API. Для статичной сетки без физики это лишний слой; отклонено: избыточная сложность.

Выбор: SwiftUI + Canvas (решение принято пользователем в разговоре).

## Ключевые решения построения (мои вызовы — проверяй при чтении)

- **Логика отделена от рендера.** Чистый `Board` (сетка, шаг, спавн еды с инжектируемым RNG для тестов) + `GameState` (`@Observable @MainActor`) как единственный владелец мутируемого состояния. Вью только рисует состояние по тикам.
- **Игровой цикл:** async-цикл на MainActor — `while running { try await Task.sleep(for: .seconds(interval)); tick() }`. Интервал пересчитывается при каждом тике из счёта → динамическая скорость без ре-таймера. Стартовое ~0.125 c/тик (8 тик/с), потолок ~0.066 c/тик (~15 тик/с); точная формула в плане.
- **Управление:** локальный NSEvent-монитор стрелок/WASD, а не `.onKeyPress` — работает без борьбы за focus окна SwiftUI; очередь из ≤2 направлений на тик (буфер клавиш), разворот на 180° отбрасывается. Мой вызов: монитор надёжнее для macOS-игры с одним окном.
- **Сетка:** 25×25 клеток, фиксированная логически; физический размер клетки = min(окно по W/H) / 25 с отступом HUD сверху (~40 pt).
- **Рекорд:** `UserDefaults` через маленький `HighScoreStore` (протокол → подделывается в тестах). В v1 — один слот «лучший счёт», таблица рекордов не нужна.
- **Пауза:** пробел; при game over ввод/пробел рестартовывает. Мой вызов: без отдельного меню паузы — клавиша + текст подсказки в HUD.

## Что остаётся на усмотрение исполнителя (детали плана)

- Точные константы (формула скорости, буфер ввода, размеры окна по умолчанию).
- Тесты: чистая логика Board/GameState покрывается unit-тестами (движение, запрет разворота, спавн вне змейки, столкновения, рост, формула скорости); рендер не тестируется.
- Структура файлов Xcode-проекта и порядок задач — в плане реализации (`docs/superpowers/plans/`).
